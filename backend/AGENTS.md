# Backend Guide

이 파일은 `backend/` 아래에 적용하며 루트 `AGENTS.md`를 보완한다.

## 책임 경계

- 백엔드는 게임방 상태, 참가 세션, 문장, 라운드, 투표, 점수 및 타이머의 유일한 진실 공급원이다.
- 전송 계층, 도메인 규칙, 저장소, 실시간 발행을 분리한다. HTTP나 WebSocket 핸들러에 점수 계산과 상태 전환 규칙을 직접 흩어 놓지 않는다.
- 외부 응답 모델은 내부 저장 모델과 분리한다. 공개 전 응답에서 `is_fake`, 정답 식별자, 개별 선택처럼 정답을 추론할 수 있는 필드를 명시적으로 제외한다.

## 도메인 불변식

- 방 코드는 충돌을 확인해 생성하는 6자리 영문·숫자 값이며 대소문자 처리 규칙을 일관되게 적용한다. 비밀값으로 취급하지 않는다.
- 같은 방의 정규화된 닉네임은 유일해야 한다. 최대 인원 확인과 닉네임 예약을 하나의 원자적 작업으로 처리한다.
- 참가자마다 공백이 아닌 서로 다른 문장 3개, 진짜 2개와 가짜 1개만 허용한다. 각 문장은 기본 5~100자이며 서버에서 검증한다.
- 공개용 문장 순서는 서버의 안전한 난수로 한 번 섞어 저장한다. 클라이언트 순서나 `is_fake` 입력 순서를 그대로 공개하지 않는다.
- 게임 시작 시 준비된 참가자만 대상으로 라운드 순서를 고정한다. 시작 이후 신규 참가 요청은 명확한 도메인 오류로 거절한다.
- 발표자는 자기 라운드에 투표할 수 없다. `(round_id, voter_participant_id)`당 최종 한 표만 존재하고, `VOTING` 동안에는 변경할 수 있다.
- 유효한 정답 투표마다 투표자에게 1점을 준다. 발표자 점수와 보너스는 항상 0이며, 결과를 여러 번 계산해도 누적 점수가 중복 반영되지 않아야 한다.
- 순위는 공동 순위를 지원하는 동일한 알고리즘을 모든 결과 API와 CSV에 사용한다.

## 상태 전환과 동시성

- 모든 진행자 명령은 현재 상태, 대상 방/라운드, 진행자 권한을 함께 검증한다. 유효하지 않은 전환은 부작용 없이 거절한다.
- 투표 마감 여부는 서버 시간으로 판정한다. `voting_ends_at` 도달 시 자동 마감하며, 수동 마감과 마지막 투표가 경합해도 마감이 확정된 뒤의 표는 집계하지 않는다.
- 상태 변경, 투표 upsert, 점수 반영은 저장소가 제공하는 트랜잭션·조건부 쓰기·잠금 중 적절한 수단으로 원자화한다. 프로세스 메모리 뮤텍스만으로 다중 인스턴스 안전성을 가정하지 않는다.
- 명령 재전송은 같은 결과를 반환하거나 이미 완료되었음을 나타내는 안정적인 응답을 반환해야 한다. 상충하는 진행자 명령은 먼저 커밋된 유효 전환만 성공시킨다.
- `PAUSED`는 이전 진행 상태와 타이머 잔여 시간을 복구할 수 있게 모델링한다. 일시 정지 중에는 투표 시간이 흐르지 않도록 서버 기준으로 처리한다.

## 인증, 보안, 수명 주기

- 참가자와 진행자 토큰은 충분한 엔트로피로 생성하고 저장 시 원문 대신 검증 가능한 해시를 보관한다. 토큰은 안전한 쿠키를 우선하며 URL, 로그, 이벤트 payload에 넣지 않는다.
- 진행자 전용 명령과 결과 다운로드는 모든 엔드포인트에서 권한을 검증한다. 클라이언트가 보낸 `room_id`, 참가자 ID, 점수, 역할을 그대로 신뢰하지 않는다.
- 입력 길이 제한, 타입/열거형 검증, 요청 크기 제한 및 엔드포인트별 rate limit을 적용한다. 저장된 문장은 로그와 모니터링 태그에서 제외한다.
- 활성 방은 일시적 네트워크 단절과 같은 브라우저의 재접속을 복구할 수 있어야 한다. 종료, 취소, 만료 시 방의 문장·투표·토큰 등 관련 데이터를 정리하고 장기 조회 API를 제공하지 않는다.
- 프로세스 재시작이나 여러 인스턴스를 지원하는 저장 방식을 택했다면, 이는 게임 종료 후 기록 보관이 아니라 활성 세션 복구 용도로만 사용한다.

## API와 실시간 이벤트

- 도메인 오류를 안정적인 오류 코드와 적절한 HTTP 상태로 매핑한다. 사용자가 조치할 수 있는 오류와 내부 오류를 구분하고 내부 상세나 비밀값을 노출하지 않는다.
- 투표 등록·변경은 PRD의 `PUT` 의미에 맞게 upsert한다. 결과 공개, 다음 라운드, 게임 종료도 재시도에 안전하게 만든다.
- 이벤트는 상태 커밋 이후 발행한다. 각 이벤트에 방/라운드 식별자와 순서를 판단할 버전 또는 갱신 시각을 포함해 오래된 이벤트를 무시하거나 재동기화할 수 있게 한다.
- `round.result_revealed` 이전에는 정답을 전송하지 않는다. `vote.progress_changed`는 익명 여부와 관계없이 진행 중에는 집계에 필요한 완료 인원만 공개한다.
- 재연결용 스냅샷 API는 역할과 현재 상태에 따라 필드를 필터링하고, 현재 선택·준비 상태·서버 마감 시각을 복구할 수 있게 한다.

## 백엔드 테스트 기준

- 상태 머신의 모든 허용/거절 전환, 문장 불변식, 발표자 투표 금지, 공동 순위와 단순 1점 계산을 단위 테스트한다.
- 동일 닉네임 동시 입장, 정원 마지막 자리, 투표 마감 경계, 중복 투표, 자동/수동 마감, 두 진행자 탭의 상충 명령을 동시성 테스트로 다룬다.
- 공개 전 모든 참가자용 HTTP 응답과 이벤트에 정답 정보가 없음을 계약 테스트로 검증한다.
- 재접속과 멱등 재시도를 통합 테스트하고, 100명 방에서 응답·전파·집계 성능 기준을 측정할 수 있는 부하 시나리오를 유지한다.
